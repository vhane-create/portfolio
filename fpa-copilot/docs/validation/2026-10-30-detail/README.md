# Mouth-detail preservation check — October 30, 2026

An optional `ARIA_DETAIL_BLEND=1` setting in the development cached renderer composites only the union of the source and generated lip regions. A feathered boundary and a skin-ring color offset reduce the change to surrounding facial detail. It uses the approved source frames and the actual neural mouth output; it does not create a replacement face or change Heart speech. It is disabled by default and does not affect the public page or pinned Mac installer.

The completed three-second neural render was processed through the new pass: all 75 frames decoded, and all pixels outside the mouth mask support matched the approved source exactly before video compression. The mask affected an average 0.6342% of the entire frame. H.264 re-encoding can change pixels outside that region in the delivered file. AAC audio packets were copied unchanged. Source, original neural render, and revised crops were visually compared at frames 0, 12, 25, 38, 50, 66, and 74. The blink remains visible at frame 66. Surrounding skin detail is retained, but the generated lips remain soft and appearance/synchronization are not accepted as finished.

Nineteen backend tests passed, including new mask bounds, invalid contour rejection, input preservation, exact preservation outside mask support, and identical-input checks. The standalone validate_detail.py command also processed the full 75-frame clip. It uses the existing completed render and existing Heart introduction segment; this is neither new speech nor a live conversational answer. The neural rendering delay, Mac performance, voice conversation and full-body goals remain unresolved.
